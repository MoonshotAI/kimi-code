# inject

Reference：需要在 setup 中取得已经由当前节点或祖先提供的依赖时使用 `inject`。

## 使用场景

- 让子节点消费所在子树的服务、配置或响应式状态，而不直接查找提供者实例。
- 依赖必须已经存在；不适合用它等待未来出现的服务，或在兄弟节点之间做服务发现。
- 兄弟共享应先把依赖放到共同祖先，见 [兄弟状态共享](../how-to-guides/sibling-state.md)。

## 调用契约

```ts
inject<T>(token: Token<T>): T
```

- 必须在同步 setup 中调用；返回找到的提供值本身，而非引用提供者槽位的包装器。
- `token` 以对象 identity 匹配；相同 `key` 的另一个 token 不等价。
- 查找顺序是自身、父节点、继续向上；每个节点只考虑该 token 尚未撤销的栈顶条目。
- 第一个命中即返回；没有提供者时同步抛出 `no provider for token '…'`，不返回 `undefined`，也没有默认值参数。
- 它不订阅提供者变化、不登记清理，也不会取得提供值的释放所有权。

## 边界

- [provide](provide.md) 必须先于对应的 inject 调用；祖先提供者应在挂载消费者之前登记。缺失依赖的消费者不会被自动延迟或重试。
- 解析是一次取值，不是动态绑定。之后新增覆盖值或撤销旧条目，已有变量仍持有当时得到的值。
- 提供的是 ref 或响应式对象时，消费者可以观察该对象内部的变化；这不等于 token 发生重新解析，也不自动解包 ref。
- 提供的是普通对象时不会凭空获得响应性；提供者换成另一个对象，也不会替换消费者已保存的引用。
- setup 外需要重新解析时，先同步保存节点，再调用 `node.resolve(token)`；它没有当前 Unit 栈要求，但同样只按调用时的祖先链取值。
- `node.providerRef(token)` 的目录可以包含兄弟及后代提供者；它不改变本函数的可见范围和最近提供者规则。
- 没有 inject 专属的取消订阅 API；消费方自己创建的 watcher 或资源应依各自 scope 与清理契约释放，见 [资源清理](../how-to-guides/cleanup-resources.md)。
