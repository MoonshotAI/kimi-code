# llm Module Guide

llm is a standalone LLM request library in `@moonshot-ai/core` (`packages/core/src/llm/`). It owns one complete request: a typed request contract, protocol encoding and decoding, streaming facts, thinking, media, error classification, and policy-driven attempts. Provider catalog state, media stores, OAuth, and turn orchestration live in agent-core-v2, which passes core request and response types directly without an adapter.

## Design Principles

1. **Minimal boundary: llm = "a single request"**. The core composes a request with `createRequester().with(...)` and returns an `LlmOutcome` from `generate`. High-level request content uses `HistoryMessage` entries and outcomes contain `AssistantEntry` values with actual model, usage, finish, and response metadata; protocol and transport consume plain `Message` values after one conversion at the execution boundary. The library does not own provider catalog refresh state, session usage ledgers, compaction, switch, the media file system, or turn orchestration. There is no second requester or compatibility event vocabulary.
2. **Streaming-native; outcomes and events have separate roles**. Core request execution returns `done / failed / aborted` as an `LlmOutcome` and emits `LlmRunEvent` values as they arrive. Completed, failed, interrupted, and retrying partial output all use the same `AssistantEntry` construction, so Loop appends history without reconstructing model metadata. `streamLlmRequest` exposes that same union as an `AsyncIterable` for transports, ending with `llm.ended` and its outcome. Streaming and non-streaming share the decoder: `stream: false` uses `send` and replays the complete response through it.
3. **The pipeline masks inter-protocol differences; protocol patches express provider customizations**. Every protocol is a `defineProtocol` object (`packages/core/src/llm/protocol/protocol.ts`): `runPipeline` composes the encode stages (cacheKey → thinking → responseFormat → maxOutputTokens → sampling → tool → message → mergeTurns → annotate → finalize → flatten), with legalize passes for media, tool-call ids, provider patterns, thinking history, and model rules. A protocol also provides its stream decoder, non-streaming replay, error decoder, and client/send/sendStream transport. Providers derive protocols with `protocol.with(patch)`; Kimi lives in `packages/core/src/llm/builtin/provider/kimi/protocol.ts`. Endpoint declarations and environment resolution use the shared implementation in `packages/core/src/llm/endpoint.ts`.
4. **Two-layer error model**. Local validation throws `SyntaxRequestFormatError` from `llm/protocol/errors.ts`, converted by `toLlmSyntaxErrorMessage`. Protocol and transport failures become `LlmErrorMessage` values inside a failed `LlmOutcome`, preserving status fields, raw errors, request ids, and protocol-provided diagnostics. A protocol can implement `diagnoseError` to extract provider-specific details from the current attempt instead of exposing a generic `traceId`. Callers consume these core error values directly without a second error union.
5. **Immutable requester configuration + scoped execution memory**. A core requester is an immutable composition of protocol, endpoint, model, profile, content, and policy dimensions. Derived requesters share an execution context containing reusable in-memory recovery entries, while each generate restores an independent ledger so concurrent calls remain isolated. Ordinary Turns and side operations reuse these entries; a successful Loop reset clears them so Undo and history replacement do not inherit stale rewrites. `ProtocolAdapterRegistry` initializes configuration at a Turn or operation snapshot; `AgentLoopService` is the only long-lived owner of the Agent-level request facade and its execution context. Other Agent services use `loopService.requester` for side requests, credentials, upload capability, and request snapshots rather than injecting another requester service. Structural projection and media resolution run per attempt through registered policies, while outer retry remains with the turn machine and Loop. Credential recovery uses the shared core policy. Reusable media entries capture stable media replacements instead of old request messages or resolver closures. The settle stage owns the attempt-scoped message accumulator, emits normalized streamed parts, judges empty responses, records timing, emits the neutral `llm.sent` fact at each actual send, and synthesizes the outcome. Each retry/recovery attempt creates a fresh accumulator; Loop consumes the final AssistantEntry for completed and interrupted history instead of maintaining another accumulator.
6. **No silent fallback**. Configuration is used exactly as given. Unsupported beta features, thinking settings, media, and empty responses fail explicitly rather than silently switching behavior. The existing main-line history policy is preserved: the core does not enable stricter tool-history verification, cleanup, or reordering as a side effect of the migration.
7. **Every variable capability is a contribution point**. Protocol patches, media upload/degradation, usage, protocol error diagnostics, and recovery plug in around the core. The core does not import v2 DI, models-dev, or provider-catalog state.
8. **Data is data**. `LlmModelSpec` and `LlmRequest` are serializable core contracts. Core messages use the existing `imageUrl/audioUrl/videoUrl` media parts; data URLs, `kimi-file://` session references, and uploaded `ms://` file ids stay in those parts. `ModelCatalog` only owns model/provider metadata and default-model selection; it does not cache requesters or expose generate/ping. Upload capability is declared by `LlmEndpoint.files`, and media resolvers receive the model and initialized requester from Loop. `SessionMediaStore.put` stores bytes and metadata and returns a `kimi-file://` reference, while `get` reads them back. ReadMediaFile only produces references; the Media Resolver resolves them on the next request using the request model, protocol media support, endpoint files, and endpoint credential recovery. The v2 history/wire message shape remains in `src/human/message.ts`; its codec preserves roles and envelopes without introducing a second media representation.
9. **Message conversion uses a compiler paradigm**. Generic messages become protocol payloads through ordered, independent patterns followed by lowering. Tool-message conversion and media mapping are patterns too. Main-line tool-result placeholders, reasoning details, and provider-specific wire behavior remain covered by the existing tests.

## Architecture

```
packages/core/src/llm/
├── message.ts                 core Message and existing media part model
├── history.ts                 HistoryEntry/AssistantEntry, metadata, constructors, and Entry→Message conversion
├── origin.ts                  prompt-origin metadata and message-origin transforms
├── context-usage.ts           HistoryEntry-based context-token estimation
├── request.ts                 model, endpoint, protocol, profile, content, and policy dimensions
├── response.ts                run/stream events, LlmOutcome, timing, and notices
├── usage.ts                   TokenUsage, stream-patch merge, and counter arithmetic
├── endpoint.ts                endpoint declarations, environment fallback, and credential resolution
├── requester.ts               createRequester + immutable .with() composition + generate
├── stream.ts                  LlmRunEvent as an AsyncIterable for transports
├── thinking.ts                shared thinking validation and effort resolution
├── generate.ts                attempt driver: encode → client → send/sendStream (+replay) → decode
├── policy/                    attempts, settlement, retries, recoveries, resolvers, and credentials
├── protocol/                  defineProtocol, pipeline, patterns, shared rules, and protocol kits
├── transport/                 headers-timeout and proxy-aware fetch
└── builtin/
    ├── protocol/              openai / openai-responses / anthropic / google-genai implementations
    ├── provider/              core requester presets, including builtin/provider/kimi
    └── policy/                built-in recoveries, including media degradation

packages/agent-core-v2/src/human/
├── message.ts                 v2 history/wire Message model and accumulator
├── provider-catalog/          refresh/upsert/remove/ping state and dual-source model merge
└── media/                     media cache, refs, resolver, store, upload, and Kimi uploads
```

Host composition lives in `agent/loop/` and `llm-adapter/`: `loopService.ts`, `projector.ts`, and `projection.ts` are ordinary objects constructed with the Loop, not scoped services. `ProtocolAdapterRegistry` only selects and initializes core requesters; profile, Loop, and klient pass `LlmRequestPart`, full `LlmRequest`, `LlmRunEvent`, and `LlmOutcome` directly without a translation layer.

Request lifecycle: a Turn or side-request snapshot resolves its configuration and context → `ProtocolAdapterRegistry` initializes a core requester with protocol, model, endpoint, credential-aware headers, timeout fetch, optional `LlmEndpoint.files`, and the Agent-scoped execution context → each Step supplies HistoryEntry content, profile, and policy in one `generate` call; `runLlmRequest` computes usedTokens from the final profile, converts Entry to plain Message once, and restores a generate-local recovery ledger from requester memory → each attempt applies inherited and newly proposed rewrites, runs ToolSelect, media-tool, structure, and media resolvers in order, then emits `llm.started` and records the resolved request → the protocol legalize/pipeline stages encode the request and filter deferred tools → the client uses `sendStream`, or `send` plus replay for non-streaming → settle produces an `AssistantEntry` with actual request metadata and emits stream facts → Loop or klient consumes the same `LlmRunEvent` vocabulary, with klient using `streamLlmRequest` directly. There is no request preview, `step.model`, or Loop-side AssistantEntry reconstruction. ReadMediaFile stays registered and only produces `kimi-file` references; the media-tool resolver hides its schema, calls, and results when the model accepts neither image nor video, and the media resolver turns references into a capability hint, an uploaded file id, or inline base64. Full compaction, cache probes, and media tools use the same Loop facade.

Tool disclosure is a request-view concern rather than an execution permission. The Agent persists an initial registry snapshot and ordered runtime changes after MCP initialization; later requests reconcile the live registry into that ledger instead of rebuilding the initial snapshot. Capable models project the active versions through deferred tools, added/removed announcements, and SelectTools schema system messages delivered by `loop.remind`. Loaded state requires the exact active schema version. A same-name modification keeps the active schema and executor pinned for the current running session and emits a reminder once per service instance instead of replacing the selection or emitting remove+add. Ordinary compaction and model switches do not apply the update; a new session uses its newly constructed registry. Models without dynamically loaded tools use only the initial top-level tools, promoting initial deferred entries in the resolver copy while keeping runtime additions filtered; runtime changes remain as content-bearing system reminders rather than dynamic schemas or select instructions. Model switches never rewrite the persisted snapshot, change ledger, or context history. Explicit tool overrides remain unchanged.

## Rejected Schemes (do not reintroduce)

- A `ModelRequester` wrapper, scoped `AgentLLMRequesterService` / `AgentContextProjectorService`, or requester access through `IModelCatalog` — core composition initializes requests, Loop owns the Agent facade, and Catalog owns only metadata.
- Splitting the request actor into llmActor / llmStreamActor — one actor per request; non-streaming also accumulates over the stream.
- A dedicated llm state machine wrapping the request actor — the turn machine invokes the actor directly and owns retry/recovery.
- DDD domain-method wrapping (Generation Domain, etc.) — use the pipeline/protocol/provider layering instead.
- Per-request trait hook objects passed to requester factories — provider customization belongs in `protocol.with(patch)` composition.
- Binding customization into format closures — providers patch the protocol spec rather than wrapping the requester.
- A second `ProviderDefinition` / `Provider.createRequester()` route — built-in providers are core requester presets, and catalogs compose them through `CatalogProviderHandle`.
- A second requester or request adapter parallel to `llm/` — callers use core request, event, outcome, and error types directly.
- Hoisting system messages out of their position on egress — system messages stay in place in history and are converted in place.
- Loop rebuilding `AssistantEntry` from a plain message plus `step.model` — llm owns the Entry contract and fills actual request metadata at settlement.
- A second Loop/turn message accumulator — settle owns the attempt-scoped accumulator and normalized stream; Loop only consumes its events and final outcome.
- Unlimited fallback for beta features — protocols are selected explicitly, and `betaApi` remains an options/model-driven opt-in.
