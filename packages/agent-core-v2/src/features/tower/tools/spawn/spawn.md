Spawn a tower worker or reviewer as a background subagent and register it in the tower roster.

Workers: pass mission_id — the tool creates the mission worktree, marks the mission active with this worker as owner, and briefs the agent with the full mission text. Artifact missions require committed deliverables and tower-recorded acceptance of the entire committed tip instead of an independent reviewer; acceptance proceeds immediately when the user has asked for the merge or approved the presented artifacts, and otherwise waits for explicit user approval. Reviewers: pass review_target — when the branch belongs to a mission, the briefing carries the full mission text (title, tasks, and any verbatim user context) plus the author's own review-request when one is on file, so the review verifies intent against the mission, not only code health; the agent must submit its verdict via TowerReview.

Model selection: Pass model only when the user explicitly requests a model for this spawn. The allowed choices are the available subagent models announced in <system-reminder>, not arbitrary [models] aliases. When model is omitted, a worker binds the configured secondary-pool default (or inherits the tower model when no pool is configured), while a reviewer always inherits the tower model.

When the branch already has history, the briefing carries it too: a worker gets the latest verdict and previous completion report, and a reviewer gets earlier review rounds so repeat findings are checked against the current tip. First spawns have no history sections. A non-clean verdict reopens a completed mission; "merged" and "abandoned" are terminal.

If the base checkout has uncommitted changes (staged, unstaged, or untracked) when a worker first spawns a branch, the tool captures them as a snapshot commit that becomes the branch's first commit — the worker starts from HEAD + that WIP. The checkout itself is never modified, and the merge gate later diffs from that snapshot while it remains in the branch's history (falling back to the base branch once a rebase drops it), so the WIP is never mistaken for the worker's own scope. Snapshotting requires the main checkout to be on the recorded base branch — a spawn with the checkout on another branch or a detached HEAD is refused; switch back to the base or commit/stash first. Re-adding an existing branch reuses it as-is.

The briefing prompt is assembled by this tool (worktree path, scope, protocol rules); use instructions only for extra context. If a worker name is already registered, resume it with Agent(resume=..., run_in_background=true, prompt="...") instead of spawning a duplicate; foreground resume is the fallback only when background task tools are unavailable. Reviewers are one-shot: after diagnosing the previous round, give a fresh reviewer a new name instead of resuming a roster agent.
