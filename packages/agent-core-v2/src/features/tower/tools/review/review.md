Submit a review verdict for a branch you were assigned to review (via TowerSpawn review_target). For an artifact mission, the tower also uses this tool to record artifact acceptance; no independent reviewer is required.

The review is stamped with the current branch tip — if the branch moves afterwards, the tower must ask for a re-review before merging. Normal merge-bound reviews come from an assigned independent reviewer. A tower-submitted build review is exceptional break-glass and must explicitly record reviewer=tower and the reason. Only those reviewers (or the tower in that exceptional case) may submit; the round number is assigned automatically.

For artifact acceptance, show the user the key artifacts and report from the latest TowerComplete acceptance-request, explain that approval authorizes the entire committed tip rather than only those key artifacts, and mention the number of additional committed files. The optional full manifest is available when the user wants more detail; reading it is not required. When the user has asked for the merge or approved the presented artifacts, record acceptance at the presented completion tip; when approval is still needed, ask for it in interactive mode, and in a noninteractive run leave the mission completed and waiting instead of merging. Never infer approval from NotifyUser, automatic tool approval, or a timeout. Then record reviewer=tower with status=clean, merge=merge, and acceptance_tip set to the completion tip shown in that request. Any later commit or rebase requires fresh acceptance. Acceptance is bound to the completion tip of the latest TowerComplete acceptance-request; if the branch tip differs, the tool refuses — have the worker run TowerComplete again at the current tip, then record acceptance on the new request. Record requested changes as non-clean feedback for rework.

The tool stores the standard review-result notifications in the same protocol flow: clean verdicts notify the tower; non-clean verdicts also notify a valid owner of an open mission, with a supervisory copy to the tower. Closed missions never wake their former author. Do not send a second manual TowerSend.

The result lists the review file and actual recipients, then reports gate semantics: for build missions, only a clean review with merge=merge on the exact tip is merge-ready; hold and fix-then-merge are not approval.
