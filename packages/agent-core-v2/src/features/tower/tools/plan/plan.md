Split the tower goal into missions. Each mission gets an id (M1, M2, …), a branch (feat/<slug>), and an isolated git worktree (.tower/worktrees/wt-N).

Write tasks as verifiable check items — the worker ticks them off, the completion report reconciles against them item by item, and the reviewer maps every one to the diff. When the user's own words carry intent your paraphrase could lose, copy the key sentences into `context` verbatim (when in doubt, include it): context supplements your paraphrase, never replaces it, and travels with the mission into the worker and reviewer briefings. Do not paste the full conversation history into it.

Use `kind: "build"` for independently reviewed code changes, `kind: "survey"` for read-only investigation, and `kind: "artifact"` for committed deliverables such as rendered results, training outputs, or analysis reports. Artifact missions need tower-recorded acceptance of the entire committed tip rather than independent review; survey missions close zero-diff without review or a real merge.

Rules enforced by the store: scopes of build and artifact missions must be pairwise disjoint or serialized by a dependency — for overlapping build or artifact scopes, the store auto-adds merge dependencies from later missions to earlier ones; workers still spawn and edit in parallel; survey missions are read-only and reserve no scope; deps must reference existing mission ids; and mission branches must be unique — a title whose slugged branch collides with any existing mission's branch (including abandoned or merged ones) or with an unowned local git branch is rejected, so rename the title and plan again. Titles must be printable ASCII English with a unique identifier word (e.g. a business code like B010100); any non-ASCII character is rejected outright. Plan once, then spawn one worker per mission with TowerSpawn.

Scope globs do not capture semantic dependencies; add explicit deps when a mission requires another mission to merge first.
