Merge a tower mission branch into the base branch (--no-ff). A zero-diff survey is the only no-op close; build and artifact missions perform a real merge.

Hard gate, enforced by the store — the mission must be completed with no open tasks or blockers and every related worker observably idle; for a build mission, its latest applicable review must be "clean" with merge recommendation "merge" on the exact branch tip (`hold` and `fix-then-merge` are never approval; only a conflict-free TowerRebase can waive the tip binding), all dependency missions must be merged or abandoned, the branch must contain the current base tip (otherwise `stale-base` — run TowerRebase for the mission first), and every changed file must fall inside the mission's declared scope. Legacy clean reviews with no merge field retain their original compatibility for build missions. An artifact mission instead requires a mission-matching reviewer=tower record with status "clean" and merge verdict "merge" on the exact tip, written only after explicit human approval of the committed artifact paths. An independent reviewer cannot substitute, a missing merge verdict is not acceptance, and rebase or any other tip move requires fresh human acceptance with no clean-rebase waiver. The scope, dependency, base, checkout, dirty-base, and real-merge checks are the same as for build. The merge also refuses when every mission record for the branch is closed (abandoned or already merged) — a merge never flips a historical mission's state; if the work must land, re-plan it under a fresh mission title. The scope diff starts from the mission's recorded spawn base while that spawn-time WIP snapshot commit is still in the branch's history, so the snapshot is not mistaken for a worker scope violation; once a rebase drops the snapshot (typically after the WIP lands on the base), the diff falls back to the base branch. On refusal, the error message tells you what to do next. After a merge, branches reported as conflicting must rebase onto the new base (TowerRebase, or the worker itself when it is mid-turn) before they can merge. If the git merge itself conflicts, it is aborted automatically — the checkout is never left mid-merge.

The main checkout must be clean for the files the merge touches: uncommitted changes in any file the merge would overwrite refuse the merge, and nothing is merged — commit or stash those changes first, then retry. This matters especially when a mission branch carries a spawn-time WIP snapshot: those changes merge into the base history, so they must not also sit uncommitted in the checkout.

When this merge closes the last open mission, the result reports the workspace ready for TowerTeardown.
