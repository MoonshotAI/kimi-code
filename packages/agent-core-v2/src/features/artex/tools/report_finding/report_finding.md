Record a confirmed finding, with evidence providing verifiable proof such as command output and logs. In a task context, pass the current `intent_id`. The returned `finding_node_id` is the exploration node ID.

- `vulnclass`: vulnerability class. `name`: vulnerability name. `severity`: `critical|high|medium|low`. `summary`: finding summary.
- `intent_id`: the current task's intent id. `asset_ids`: affected asset ids.
- `evidence`: evidence/PoC text — the command and the key output lines that prove the conclusion.
- `counterevidence` (optional): what you tested that did NOT work (variants, paths, or bypasses that were blocked or came back negative). Fill it when your confidence is not high; omitting it never blocks reporting.
- `confidence_rationale` (optional): why you are confident this is a real, exploitable issue rather than a false positive.
- `traffic_refs` (optional): when corresponding recorded traffic exists, first verify against the real records with traffic_search / traffic_get, then bind in reproduction order; each ref is `{traffic_id, role, note}` with role one of baseline / proof / verification / supporting, and the note stating which conclusion this traffic supports. Only a proof or verification body can make a finding verified. For TCP, no-capture, or no exact match, omit this and write the report from textual/command evidence.
- `confidence_level` (optional): proof-of-exploitation level 1-4: 1 error/timing/response variation, 2 structural manipulation (boolean, UNION, parser difference), 3 actual data extracted, 4 critical impact (admin credentials, code execution). L3 is the minimum for verified. Omit when not proven. Do not raise confidence_level to get a verified status.
- `evidence_quotes` (optional): exact lines copied from a bound proof/verification response body (read it with traffic_get first). Never from memory or from the report text; each quote is checked byte-for-byte against a bound record. If you cannot quote the proof, omit the quotes: the finding then stays unverified, which is acceptable.

Report only findings you have actually confirmed. Before reporting, check this task's existing findings (list_findings) to avoid reporting the same finding twice. A finding is verified only when confidence_level is at least 3, a proof/verification body is bound via traffic_refs, and every evidence_quote appears verbatim in one of those bodies; otherwise it is saved as unverified with the reason. Keep your verification commands and key output in `evidence` so they can be traced.
