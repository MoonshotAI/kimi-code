# 01 · 环境搭建与运行

> 时效基线：基于 commit `d4e0ad4b2`（2026-08）。

## 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | **≥ 24.15.0** | 仓库根 `.nvmrc` 固定为 `24.15.0`；nvm / fnm / mise 都会读它 |
| pnpm | **10.33.0** | 根 `package.json` 的 `packageManager` 字段锁定 |

`.npmrc` 开了 `engine-strict=true`，版本不对 `pnpm install` 会直接失败——遇到安装报错先查版本：

```bash
node -v   # 应 ≥ v24.15.0
pnpm -v   # 应为 10.33.0
```

## 安装与构建

```bash
git clone <repo> && cd kimi-code
pnpm install          # 触发 postinstall：node-pty 权限修复、CLI 资源准备
pnpm build            # 全量构建所有包（tsdown 产物，供依赖方消费）
```

日常开发大多**不需要**全量 build：`dev:*` 脚本用 tsx 直接跑 TS 源码。但两类场景需要先构建过 packages：

- 跑 `apps/kimi-code` 的 `test` / `e2e`（脚本里自带 `pnpm -w run build:packages`）；
- 根 `pnpm typecheck`（第一步就是 `build:packages`）。

## 常用命令速查（仓库根 `package.json`）

| 命令 | 作用 |
|---|---|
| `pnpm dev:cli` | 开发模式跑 CLI/TUI（tsx 直跑 `apps/kimi-code/src/main.ts`） |
| `pnpm dev:cli:legacy` | 同上，但强制 v1 引擎（`KIMI_CODE_LEGACY_FLAG=1`） |
| `pnpm dev:server` | 启动 `kimi web` 开发服务器（kap-server，带 `--debug-endpoints`） |
| `pnpm vis` | 启动会话可视化回放工具（vis） |
| `pnpm dev:docs` | 本地起 VitePress 文档站（独立安装，不进 workspace） |
| `pnpm build` / `build:packages` | 全量构建 / 只构建 packages/* |
| `pnpm test` | vitest workspace 全量单测（packages/*、apps/kimi-code、apps/vscode） |
| `pnpm typecheck` | 先 build packages 再逐包 tsc |
| `pnpm lint` / `lint:fix` | oxlint（含无注释区检查 `scripts/check-no-comments.mjs`） |
| `pnpm changeset` | 生成变更集（发版用，见 `07`） |

## 跑通三种形态

### 1. CLI / TUI

```bash
pnpm dev:cli
```

`apps/kimi-code/scripts/dev.mjs` 会先起一个隔离的插件市场 dev server，再用 tsx 从仓库根目录运行 `src/main.ts`。首次使用在 TUI 里输入 `/login` 完成 OAuth 登录（也会写 `~/.kimi-code`），然后就能对话了。

只想要裸 CLI 进程（便于挂调试器）用：

```bash
pnpm -C apps/kimi-code run dev:cli-only
```

### 2. VS Code 插件

用 VS Code **打开 `apps/vscode` 目录作为工作区**，按 F5 选 "Kimi Code: Extension Development Host (isolated)"。会自动：构建隔离沙箱（`.tmp/vscode-extension-dev/`，含独立的 user-data / 扩展目录 / kimi home / 空工作区）、起 extension 与 webview 的 watch、再拉起一个新的 Extension Development Host 窗口。详见 `03-调试指南.md`。

### 3. Web 服务器（kap-server）

```bash
pnpm dev:server
```

即 `apps/kimi-code` 的 `dev:server` 脚本：`KIMI_CODE_DEV_SERVER=1 tsx ... src/main.ts web --no-open --debug-endpoints`。起在回环地址并带 bearer 鉴权；`--debug-endpoints` 挂载 `/api/v1/debug/*` 自省 RPC（供 kimi-inspect 使用）。配套浏览器 UI 见 `apps/kimi-code/dist-web`（预构建产物，源码在外部 code-app 仓库）。

> `dev:server` / `dev:kap-server` / `dev:v2` 三个脚本当前是完全相同的命令，属历史别名。

## 配套工具

| 工具 | 启动 | 用途 |
|---|---|---|
| kimi-inspect | `pnpm --filter @moonshot-ai/kimi-inspect dev` | 网页查看运行中 server 的会话、transcript、DI 单元树；Vite 代理到 `KIMI_SERVER_URL`（默认 `http://127.0.0.1:58627`），并自动发现 `~/.kimi-code/server/instances` 下的实例 |
| vis | `pnpm vis` | 会话/回放可视化（默认 web 5173、API 5174） |
| 文档站 | `pnpm dev:docs` | 用户文档本地预览 |

## 数据目录与隔离

所有形态的数据根由 `KIMI_CODE_HOME` 决定，默认 `~/.kimi-code`：

- `~/.kimi-code/config.toml` — 配置（模型、provider、MCP）
- `~/.kimi-code/` 下还有会话记录、OAuth 凭据、插件、搜索索引等
- **VS Code 插件与 CLI 共享同一个 home**——配置、登录态、会话互通；因此同一会话不要同时在两个入口打开
- 做实验想不污染正式数据时，给命令前缀 `KIMI_CODE_HOME=/path/to/sandbox`（插件 F5 的隔离配置就是这么做的）

## 测试

```bash
pnpm test                                   # 全量（根 vitest.config.ts 串起各 workspace 项目）
pnpm --filter @moonshot-ai/agent-core-v2 test   # 单包
pnpm -C apps/vscode test                    # 插件单测
```

两个例外要记住：`packages/pi-tui` 用的是 node:test 而非 vitest；`apps/kimi-inspect` 的测试不在根 vitest projects 列表里。CLI 的 e2e 在 `apps/kimi-code`：`pnpm e2e`（mock）与 `e2e:real`（真实 LLM 冒烟）。
