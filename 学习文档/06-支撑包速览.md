# 06 · 支撑包速览

> 时效基线：基于 commit `d4e0ad4b2`（2026-08）。每包半页，够你决定"要不要深入"。

## packages/kosong — LLM 抽象层（v1 栈）

`generate` / `provider` / `message` / `tool` / `capability` / `usage` 的最小抽象，provider 实现在 `src/providers/`（kimi、anthropic、openai-legacy、openai-responses、google-genai 等）。v1 引擎和 node-sdk 的 v1 路径用它；**v2 引擎不用它**——`packages/agent-core-v2/src/kosong/` 内嵌了演化版（contract/model/protocol/provider）。两者的关系是"原型与分叉"，不是"接口与实现"。

## packages/kaos — 执行环境抽象（v1 栈）

进程/shell/文件系统的 seam：`environment.ts`、`local.ts`、`ssh.ts`（`export './ssh'`）、`process.ts`。v1 引擎和 acp-adapter 用；v2 有自己的 `src/os/` + `src/runtime/`。

## packages/agent-core — v1 引擎（遗留）

`Agent` 类（`src/agent/index.ts`）+ 进程级门面 `KimiCore`（`src/rpc/core-impl.ts`）。现在只作为 `KIMI_CODE_LEGACY_FLAG` 的回退路径存在，但 `src/loop/` 这一个目录仍然值得读：`run-turn.ts`（turn 收敛、abort/compaction 安全点、max steps）、`turn-step.ts`（单步 LLM 请求）、`tool-call.ts` / `tool-scheduler.ts`（工具批调度：按资源冲突决定并行/串行）——它刻意设计成无状态、不 import 宿主实现，是理解 agent loop 的最简读本（v2 的 loop 是它的 DI 化移植）。`src/tools/builtin/` 下每个工具一个 `.ts` + 一个 `.md` 描述文件，这个"工具描述即文档"的形式被 v2 延续。

## packages/transcript — 同构 transcript 数据层

把会话日志投影成 UI 可消费数据的四层设计：L1 agent 粒度存储、L2 幂等操作（op-batch）、L3 `off/turn/block/delta` 粒度订阅、L4 无框架视图注册，外加 turn 游标分页。纯 TS、浏览器安全、拥有 transcript 契约类型的唯一所有权（`src/contract/`）。消费方：kap-server 的 transcript REST/WS 面、kimi-inspect。冷重建时用 `src/history/groupTurns.ts` 折叠 `wire.jsonl`。做"自己渲染会话数据"的功能时从这里入手，别直接解析 wire 文件。

## packages/minidb — 嵌入式 JSON 文档库

kap-server 搜索索引的后端：快照 + WAL 持久化、独占写锁、比内存大的全文倒排层、持久化的索引世代。想在本地给 agent 做个可查询存储时的现成轮子。详见 `packages/minidb/AGENTS.md`。

## packages/protocol — 服务器协议 schema

REST 信封（`{ code, msg, data, request_id }`）、错误码、分页、WS 控制消息的 zod 定义，kap-server 与客户端共享。写对接 `kimi web` 的客户端时以它为准；HTTP API 文档在 `docs/en/reference/server-api.md`。

## packages/oauth — Kimi OAuth 工具

设备码流程、托管鉴权、MCP OAuth 令牌事务。登录相关功能（CLI `kimi login`、插件 `auth.handler.ts`）的底层。

## packages/telemetry — 遥测基础设施

客户端共享的事件上报设施。v2 引擎里遥测事件用 `defineTelemetryEvent` 声明式定义（详见 `packages/agent-core-v2/AGENTS.md` 的遥测节）。

## packages/pi-tui — 终端 UI 库

内嵌的 pi-tui（上游 0.80.2 基线 + 有守卫的本地分叉）。CLI 的 TUI 全部建在它上面；测试用 **node:test** 而非 vitest。改 TUI 前必读 `.agents/skills/write-tui/SKILL.md`。

## packages/tree-sitter-bash — 纯 TS bash 解析器

无运行时依赖、无 wasm 的 bash 解析器，输出对齐 tree-sitter-bash 节点类型。v2 引擎用它分析 shell 命令（比如判断命令是否安全/涉及哪些路径），在确定性预算内运行，解析失败按"无法分析"降级。只做解析、不做安全判断。

## packages/migration-legacy — 旧数据迁移

把旧版 kimi-cli 的 `~/.kimi/`（配置、MCP、历史、skill、会话）迁到 `~/.kimi-code/`。CLI 与插件都调用（插件里就是 `src/migration/legacy-migration.manager.ts` 那套提示 UI）。

## packages/acp-adapter 与 acp-server — ACP 双代

- `acp-adapter`：v1 时代的适配器，把 node-sdk harness 翻译成 Agent Client Protocol（stdio JSON-RPC）；`kimi acp`（遗留开关）使用。
- `acp-server`：v2 原生 ACP 宿主，直接经 klient memory facade 接 agent-core-v2；`kimi acp --native` 使用。
  想让 Zed/JetBrains 等编辑器驱动 kimi 时才有用；作为"第三方协议适配层怎么写"的参考也有价值。

## packages/klient — 契约驱动客户端（详见 04）

`global.*` / `session(id).*` / `agent(id).*` 三段 facade + zod 契约 + ipc/memory 双传输。它是所有非 REST 宿主访问 v2 引擎的正规通道。
