# 生成学习文档

为陌生代码库生成"能读懂"的学习文档——范式全部由本技能自身定义（骨架/规范/自检）,不依赖任何特定仓库。与 `save-plain-language` 的分工：那个管**改已有文档**，本技能管**从零生成**——判断标准是**产出性质,不是问题大小**："XX 是怎么工作的"最终产出一篇新文档,也算生成。

## 两种规模

- **整套系列**（整个仓库的导读体系）：走完整步骤,先出目录方案;
- **单篇深潜**（聚焦一个模块/机制）：跳过目录方案,只给一段迷你提纲（要讲清哪几问）经确认后成文;写作规范与自检同整套。

## 调研问题模板（摸底的提问范式,源自 kimi 官方 `docs/zh/guides/use-cases.md`"理解陌生项目"一节）

整体梳理（一篇"项目全貌"正好由这四问展开成章节）:

```
帮我梳理这个仓库的整体架构。重点说清楚：
1. 入口在哪里，启动后做了什么
2. 主要模块之间的依赖关系
3. 配置和数据的加载流程
最后画一张简单的模块关系图。
```

聚焦深潜（对应单篇专题文档）:

```
src/runtime 下的 event loop 是怎么工作的？事件从哪里产生、又被谁消费？
```

```
这个项目里「权限审批」是怎么实现的？涉及哪些文件，关键类型是什么？
```

大型调研可派发 subagent 并行摸底子模块。

## 步骤

1. **先摸底再动笔**：仓库布局（apps/packages）、根 AGENTS.md 与各包 AGENTS.md/README、package.json scripts（构建/运行/测试方式）、已有的架构文档——都是素材。架构事实的第一来源是仓库自己的文档,学习文档只在"学习动线"层面组织它们,不复制粘贴。
2. **先出目录方案（plan）**：给文档地图——每篇一句话定位 + 阅读顺序 + 分阶段学习路线,经用户确认再写正文。篇数由**覆盖**决定:先对照仓库实际列模块/链路清单,该覆盖的主题一篇不少;但每篇必须有真深度（机制 + 代码坐标 + 实测）——写不出深度的主题并入相邻篇,不为凑数单独成篇。**防两种失败:凑数灌水篇,和为省事漏主题。**（单篇深潜改为迷你提纲,见"两种规模"。）
3. **每篇的骨架**（可裁剪）:
   - 头部引用块:时效基线（基于 commit + 日期,注明"行号会漂移,以路径为准"）、写给谁、与相邻篇的分工;
   - `## 〇、全局认知`:3–5 条一句话核心事实,先给心智模型;
   - `## 一、二、三…` 中文序号主章节,小节用 `1.1/2.3` 数字编号;文末"下一步"指向相邻篇。
4. **写作规范**（同 save-plain-language）:术语 + 括号人话加注;压缩语展开成因果链;结构优先（表格管一一对应、列表管并列、子列表不折叠）;涉及代码必给 `文件:行号`,**关键处附源码原文片段**（别只给行号——读者不应被迫跳去源码才能看懂）;事实先核对——行号/脚本/配置一律 grep/read 验证,关键结论尽量**实测**（真跑一次命令）,测不了就标注"未验证"。
5. **交叉引用禁用 §**:写"第 X 节/X.Y 小节",跨文档写"`NN` 第 X 节"。写完 grep 一遍 § 确认清零。
6. **术语集中**:系列里建统一术语表（如 `术语表.md`,黑话→人话分组表格,含代码坐标）;此后新黑话只进术语表,各篇正文只留引用。
7. **收尾与自检**:README 建文档地图（篇名/内容/什么时候读）+ 学习路线;自检——§ 清零、抽查代码坐标有效、**对照步骤 2 的模块清单无遗漏主题**、每篇能回答"读者什么时候读它"。

## 红线

- 不凭印象写行号/命令/引文,写前核对;关键断言优先实测。
- 不复制 AGENTS.md/README 原文充数——重组为学习动线。
- 不用 § 符号;不写没有信息量的客套话与空洞总结。
- 对话中讨论过的解释若要落进文档,以对话版本为源稿原样移植（见 save-plain-language）。
