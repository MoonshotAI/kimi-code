# 保存对话实录

把当前对话整理成一份"原始实录"文档,写进仓库的 `docs/`。定位:不是总结重构,而是忠实按对话原顺序记录发生了什么、查到了什么、改了什么——排查路径(包括走弯路)本身就是价值。

## 步骤

1. **摸清惯例**:`ls docs/` 看已有文档的命名与格式,沿用并顺延。AgentOnWechat 仓库的惯例是 `M<N>-<主题>.md`(已有 M7 则新的用 M8,拿不准就选一个合理的编号,并在交付说明里告知可改名);无可参照惯例时用 `YYYY-MM-DD-<主题>.md`。
2. **重建对话**:凭当前上下文按原顺序整理。用户每条消息直接作三级标题:`### <原话>`(逐字保留,含错别字;多行或过长时压成一行,不改原意),标题下直接接 assistant 回答——保留关键论证与结论,可压缩寒暄。不加"问/答"标签。
3. **补全已有档——插入还是追加**:同一对话第二次(及以后)存档是补全,不是一律追加到文末,按文档形状定:
   - **有收尾节**(成果清单/总结/"下一步"之类):新增问答按发生时间**插到收尾节之前**(实录要按对话时序);收尾节的表格与结论**同步合并更新**(终态要准)。收尾永远保持在最后——读者在总结处停下时,总结必须已覆盖全文。
   - **没有收尾节**(纯时序实录,无总结):文末就是时间线最新处,新内容按时间顺序**直接追加文末**。
   - 简记:**事件按时间插位,变更并入清单;若有总结,总结必须最后**。
4. **工具调用**:保留命令与关键输出,格式:

   > **Bash**:`命令`
   > ```text
   > 关键输出
   > ```

   只留有信息量的输出:发现的状态、验证结果、报错、被拒记录(被拒本身常是剧情一部分)。读文件类调用注明路径与关键发现即可,不大段粘贴文件内容。对话中引用代码的解释,其中的代码片段原样保留——别在存档时把片段降级成只有行号。
5. **文档头**:标题 + 引用块:
   > `> YYYY-MM-DD[,接《上一篇档名》]。原始对话内容,仅去除界面噪音;工具调用保留命令与关键输出。`
   可加一行背景(对话开始时的状态/动机)。
6. **中途变更注明**:对话期间用户自己做的改动(如重命名文件、手改配置)要写进对应位置,避免后读者误解时间线。
7. **成果清单**:若对话产生了代码/文件改动,结尾加变更表格(文件 → 变更)+ 使用/恢复要点。
8. **交付说明**:告诉用户文件路径;编号若是推断的,说明可改名。

## 红线

- **凭据/token/密钥绝不写入**(对话中读到的 API token、密码等一律以"(敏感字段略)"标注)。文档会进 git,一旦写入就进了历史。
- 用户原话不润色、不纠错;只有 assistant 部分可压缩。
- 不在 git 仓库里时,先问存哪,不要默默往 cwd 丢文件。

## 补充

- 若用户同时提供了终端导出的原始 .txt(带界面噪音),可一并保存并在文档头注明"原始导出一并存档"。
- 用户没说位置时默认当前仓库 `docs/`。
- 用户没说新建文档保存的话,默认保存到当前对话中已经写入过的文档。
