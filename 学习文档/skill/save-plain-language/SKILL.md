# 人话改写

用户维护学习笔记(或任何面向人阅读的文档)时,会不断追问文中的缩写、行话、抽象词。本技能约束两类动作:**解释黑话**与**把解释写进文档**。

## 解释黑话

1. **术语保留 + 括号内人话加注**,不删术语本身——读者以后还会在别处遇到它,要建立"术语 ↔ 人话"的对应。
2. **压缩语展开成因果链**:"XX 从 src 消费""三级回退""回环+bearer"这类话,展开为"谁 → 做什么 → 为什么 → 对读者意味着什么"。
3. **结构优先**:分层小标题、表格、编号列表。一一对应的关系用表格;并列的手段/条件用列表;禁止把多层信息塞进一个长括号。
4. **事实先核对再写**:行号、脚本定义、配置项,先在仓库里 grep/read 验证;拿不准就标注"未验证",宁可少写不可写错。
5. **涉及代码必给坐标,并附必要代码**:凡提到函数/脚本/配置/命令定义,附 `文件路径:行号`（如 `package.json:8`、`src/cli/sub/web/run.ts:50`）——对话里可点击跳转,读者可自行验证;行号随代码演进会漂移,引用以当前仓库为准。**别只给行号**:关键处附上源码原文片段（几行即可,写前核对）——读者不应被迫跳去源码才能看懂。
6. 先答后改:用户问"X 是什么意思"时,先在对话里给出条理化解释;然后再动文档。

## 把解释写进文档

1. **对话里的答案就是源稿**:写入文档时**逐字复制对话原文**,只允许三类改动——删寒暄、调衔接词、合并明显重复。结构(小标题、表格、编号、子列表)与**句序**原样保留;同义改写、把多条合成一条、替读者"提炼" = 违规。**自查标准:文档里每一句都要能在源稿中找到原句——只许删、不许添**(衔接词除外);小标题也用源稿自己的标题,不自造,**且独立成行,不与后句拼在同一行**。源稿每一条子弹/表格行在文档里都有对应句,反之亦然,数目不许少。自查要覆盖**整段全部内容**,不许只查本次改动的片段。**一段只对应一个源稿回合**——不同回合的回答不许拼接成一块;挪动某段时,它的标题、编号、收尾句必须整体跟走,不许丢。
2. **严禁二次压缩**:把整套解释压成一句带巨型括号的密集长句 = 错误。文档质量不得低于对话。
3. **代码坐标与片段原样带入**:对话解释中给出的 `文件路径:行号` 引用,写进文档时全部保留,不得省略成"见某文件";对话里的代码片段同样原样带入,不得降级成只有行号。
4. **新术语只进统一术语表**:若该文档系列已有 glossary 文件,新黑话只加进术语表,正文留一处引用,不在各篇重复维护。
5. 若系列没有术语表而黑话反复出现,建议用户建一个(如 `术语表.md`),此后只改它。

## 红线

- 不删术语、不只用大白话替换——永远"术语 + 人话"并存。
- 不凭印象写行号/命令/配置原文,写前核对。
- **交叉引用禁用 § 符号**:写"第 X 节/X.Y 小节";跨文档写"`NN` 第 X 节"、"`NN` 的 X.Y 小节"。
- 用户手改过的段落视为定稿基准,除非被要求,不主动重写。
