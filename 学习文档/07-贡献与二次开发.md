# 07 · 贡献与二次开发

> 时效基线：基于 commit `d4e0ad4b2`（2026-08）。权威来源是 `CONTRIBUTING.md`（中英对照）与根 `AGENTS.md`，本文是学习向摘要 + 二次开发切入点。

## 一、贡献流程要点

- **门槛**：外部 PR 只接受维护者在 issue 上 `/approve` 过的 bug 修复；功能由团队实现。约 100 行以上的重构/API 变更先开讨论。AI 辅助的贡献按同样标准——"你必须能解释你提交的每一行"。
- **提交与 PR 标题**：Conventional Commits（`feat:` `fix:` `docs:` `chore:` `refactor:` `test:` `ci:` `build:` `perf:` `style:`），PR 标题由 CI（pr-title-checker）强制检查。
- **每个 PR 自动跑**：lint（含无注释检查）、typecheck、test（分片）。本地对应：`pnpm lint && pnpm typecheck && pnpm test`。
- **changeset**：影响发布产物的 PR 必须带一个 `.changeset/` 条目（`pnpm changeset`）。**只有两个可发布包**：`@moonshot-ai/kimi-code`（CLI）和 `@moonshot-ai/kimi-code-sdk`；其余 workspace 包在 ignore 列表里（内部依赖的影响要自己判断升级级别）。纯文档/测试/CI 的 PR 可免。写法规则见 `.agents/skills/gen-changesets/SKILL.md`：一句话、只说用户可感知的变化；不确定 bump 级别（patch/minor）就用 minor，**major 必须先和用户确认**。
- **用户文档**：改动用户可感知行为时同步更新 `docs/`（双语镜像，规则见 `docs/AGENTS.md`）。

## 二、写代码前必知的硬约定

来自根 `AGENTS.md` 与 CI，违反会直接挂：

1. **无注释区**：`packages/agent-core-v2`、`packages/kap-server`、`packages/transcript` 里不允许行/块注释；允许的只有导出符号的 JSDoc 与 lint 抑制指令。`scripts/check-no-comments.mjs` 在 `pnpm lint` 里跑。
2. **workspace 增删包要同时改两处**：`pnpm-workspace.yaml` **和** `flake.nix`（后者的 `workspacePaths`/`workspaceNames` 是手维护的，漏了会静默坏 Nix 构建；自动检查只覆盖 kimi-code 的依赖闭包，不可全信）。
3. 可选属性直接传 `undefined`，不要条件展开；可选属性类型不要写 `| undefined`；单参内部方法不要为了风格包一层 options 对象。
4. 非包入口的 `index.ts` 用 `export * from './module'`。
5. 导入优先 `#/...`（包内别名）。
6. 不要新增零散测试文件——往对应模块的现有测试文件里加用例。
7. 测试因你的改动而挂：默认先改测试，除非实现确实有 bug。
8. 提交信息与 PR 描述**不出现 agent 署名/co-author**；开 PR 前用 `git status` / `git diff --staged --stat` 清掉草稿类文件（学习笔记放 `.tmp/`，该目录被 gitignore）。

## 三、二次开发切入点

### 给引擎加一个工具（最常见的扩展）

位置：`packages/agent-core-v2/src/agent/tools/`。一个工具 = 定义文件（schema + 描述，参照 `os/`、`edit/` 现有写法，描述常放同名 `.md`）+ 通过工具贡献通道注册（内置走 `registerAgentToolService`/builtin assembly；也可做成 Feature 用 `contributeTool`）。配套：权限归类（`permissionGate`/`toolPolicy` 里决定是否需要审批）、测试加在对应现有测试文件里。v1 引擎的 `packages/agent-core/src/tools/builtin/` 可对照。

### 给 VS Code 插件加功能

固定"三处联动"：

1. `apps/vscode/shared/bridge.ts`：加 `Methods`/`Events` 常量；
2. `apps/vscode/src/handlers/`：实现宿主侧（能用 `vscode.*` API 的地方）；
3. `apps/vscode/webview-ui/src/`：`services/bridge.ts` 加调用 + 组件/store 消费。
   需要引擎配合的（如新的会话操作）再往下走 node-sdk → klient 契约。

### 把引擎嵌进自己的宿主

用 `@moonshot-ai/kimi-code-sdk` 的 `createKimiHarnessV2`，完整范例就是 `apps/vscode/src/runtime/kimi-runtime.ts`（约百行就把 harness 跑起来了）。想跨进程就换 klient 的 ipc 传输，或直接部署 kap-server 走 REST/WS。

### 给服务器加接口

`packages/kap-server/src/routes/` 加路由（信封/分页用 `packages/protocol`），OpenAPI 面同步更新；别忘了 `/api/v1/AGENTS.md` 里的约定（会话路由必须走 `sessionIndex → handlerFor → handler` 组合链）。
