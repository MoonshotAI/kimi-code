# 03 · 调试指南

> 时效基线：基于 commit `d4e0ad4b2`（2026-08）。
> 仓库里**唯一提交了的 launch 配置**在 `apps/vscode/.vscode/launch.json`；CLI 与 server 的调试靠附加（attach），本文给出可复制的配置。

## 总览：调试什么 → 用什么方法

| 目标 | 方法 | 见章节 |
|---|---|---|
| VS Code 插件（宿主侧 TS） | F5 现成配置，断点直落 `src/` | §1 |
| 插件 webview（React） | Webview Developer Tools | §2 |
| CLI / TUI | JavaScript Debug Terminal 或 attach | §3 |
| kap-server（`kimi web`） | 同上 + kimi-inspect 观测 | §4 |
| 单元测试 | vitest + JS Debug Terminal | §5 |
| 会话数据 / 回放 | vis | §6 |

## 1. VS Code 插件：F5（最顺的一条路）

**前提**：用 VS Code 把 `apps/vscode` 目录**作为工作区打开**（launch.json 里的 `${workspaceFolder}` 指向它），已执行过根目录 `pnpm install`。

**步骤**：

1. 按 `F5`，选 **"Kimi Code: Extension Development Host (isolated)"**。
2. `preLaunchTask: vscode: dev`（`apps/vscode/.vscode/tasks.json`）会并行跑三件事：
   - `pnpm run dev:prepare`：在仓库根 `.tmp/vscode-extension-dev/` 下创建一次性沙箱——独立的 `user-data/`、`extensions/`、`kimi-home/`（作为 `KIMI_CODE_HOME`）、空 `workspace/` 文件夹；
   - `pnpm run dev:extension`：tsdown watch 构建 `dist/extension.js`，**带 sourcemap**（`scripts/watch-extension.mjs` 轮询触发，见下面"改哪些代码会生效"）；
   - `pnpm run dev:webview`：vite watch 构建 webview（`--sourcemap`）。
3. 弹出新的 "Extension Development Host" 窗口：干净的隔离配置、打开的是沙箱 workspace、插件数据完全隔离（不碰你真实的 `~/.kimi-code`）。首次要在里面重新登录。
4. 在**原窗口**的 `apps/vscode/src/**` 下断点，宿主窗口里操作即可命中（launch.json 已开 `sourceMaps` 并限定 `resolveSourceMapLocations` 到本目录）。

**改哪些代码会自动生效**（`scripts/watch-extension.mjs:9-22` 的轮询列表）：

- `apps/vscode/{src,shared}` + `packages/{agent-core,kaos,kosong,migration-legacy,node-sdk,oauth,protocol,telemetry}/src`——改动后自动重打包，然后在宿主窗口 **Developer: Reload Window** 重新加载扩展。
- **不在列表里**：`agent-core-v2`、`klient`、`transcript`、`minidb` 等。这些包打进插件时取的是它们的**构建产物 dist**（tsdown 只 alias 了上面那几个包，见 `apps/vscode/tsdown.config.ts:21-28`）。改 v2 引擎代码后要：`pnpm build:packages`（重建相关包）→ touch 一下 `apps/vscode/src` 任意文件（触发重打包）→ Reload Window。
- 由于这些包以 dist 进 bundle，**在 `packages/agent-core-v2` 源码里下的断点可能不命中**；调试引擎内部时建议改用 §3 的 CLI attach 方式，或在 node-sdk facade 层下断点。

**webview 重载**：宿主代码改动用 Reload Window；webview 改动 watch 重建后，可用命令面板执行 `Kimi: Reset`（`kimi.resetKimi`）或直接 Reload Window。

**日志**：命令面板 → `Kimi: Show Logs`（插件的 "Kimi Code" 输出通道，`src/extension.ts:20` 创建）；`SessionRuntime` 的错误也汇到这里。

## 2. 插件 webview 调试

webview 是独立的 Chromium 沙箱。在**宿主窗口**（Extension Development Host 那个）命令面板执行：

```
Developer: Open Webview Developer Tools
```

会打开 webview 专属的 DevTools：Console 里看 React 报错、Sources 里（watch 构建带 sourcemap）可直接给 `webview-ui/src/**` 下 `debugger`/断点、React DevTools 也可装在宿主窗口用。zustand 状态可以直接在 Console 里观察 store。

## 3. CLI / TUI 调试（attach 模式）

没有现成 launch.json，两种做法：

**做法 A（推荐）：JavaScript Debug Terminal**

1. VS Code（打开仓库根）命令面板 → **JavaScript Debug Terminal**，得到一个自动 attach 的终端；
2. 在里面跑：

   ```bash
   pnpm -C apps/kimi-code run dev:cli-only
   ```

   （裸 tsx 命令：`tsx --import ../../build/register-raw-text-loader.mjs ./src/main.ts`；要完整 dev 环境——含隔离插件市场——用 `pnpm dev:cli`，但它是 `scripts/dev.mjs` spawn 的子进程，自动 attach 不一定递归，此时用做法 B）
3. 断点下在 `apps/kimi-code/src/**` 或任何 workspace 包**源码**里（tsx 直跑 TS，sourcemap 天然成立）——这正是调试 `agent-core-v2` 内部的最佳方式。

**做法 B：inspect 端口附加**

```bash
NODE_OPTIONS=--inspect pnpm -C apps/kimi-code run dev:cli-only
# 或对已运行的进程：命令面板 → Debug: Attach to Node Process → 选 tsx 子进程
```

再配一个个人 `.vscode/launch.json`（放仓库根，`.vscode/` 未提交，属个人配置）：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Attach to kimi dev CLI",
      "type": "node",
      "request": "attach",
      "port": 9229,
      "restart": true,
      "resolveSourceMapLocations": null,
      "skipFiles": ["<node_internals>/**", "**/node_modules/**"]
    }
  ]
}
```

**TUI 注意**：断点挂起会冻结整个 TUI 渲染，属正常现象；resume 即恢复。TUI 与调试输出混在同一个终端会花屏，建议让被调试进程跑在普通终端、调试器只附加（做法 B），或调试非交互子命令（如 `web`）。

## 4. kap-server（`kimi web`）调试与观测

**启动**（仓库根）：

```bash
pnpm dev:server
```

实际命令：`KIMI_CODE_DEV_SERVER=1 tsx ... src/main.ts web --no-open --debug-endpoints`（定义在 `apps/kimi-code/package.json` 的 `dev:server`）。特点：

- 绑定**回环地址**并启用 bearer 鉴权（默认安全，不暴露局域网）；
- `--debug-endpoints` 挂载 `/api/v1/debug/*` 反射 RPC——整个 DI 注册表的自省面；
- 日志：`--log-level debug`（`apps/kimi-code/src/cli/sub/web/run.ts` 的子命令选项）或 `KIMI_LOG_LEVEL`；
- `KIMI_CODE_DEV_SERVER=1` 时容忍缺失的 `dist-web`（浏览器 UI 来自外部 code-app 仓库的预构建产物）。

**断点**：与 §3 相同——JS Debug Terminal 里跑 `pnpm dev:server`，或在 web 子命令入口 `apps/kimi-code/src/cli/sub/web/run.ts` 与 `packages/kap-server/src/**` 下断点。

**观测（强烈推荐）**：另开终端跑

```bash
pnpm --filter @moonshot-ai/kimi-inspect dev
```

kimi-inspect 是网页版调试器（Vite 代理 `KIMI_SERVER_URL`，默认 `http://127.0.0.1:58627`），并**自动发现** `~/.kimi-code/server/instances/` 下的运行实例（每个实例一个 `<serverId>.json` 元数据，见 `packages/kap-server/src/instanceRegistry.ts:210`），从页头下拉切换。能看：workspace/session 浏览、逐会话 transcript 对话、跨会话搜索、Service 面板、DI 单元树/级联视图。

直接 curl 调试面：从实例 JSON 里取连接信息，`curl -H "Authorization: Bearer <token>" http://127.0.0.1:<port>/api/v1/debug/...`（只在回环可用）。

## 5. 单元测试调试

```bash
pnpm test                                  # 全量（根 vitest workspace）
pnpm --filter @moonshot-ai/agent-core-v2 test
pnpm -C packages/agent-core-v2 exec vitest run src/agent/loop     # 只跑某目录/文件
pnpm -C apps/vscode test                   # 插件 16 个套件
```

- 按用例名过滤：`vitest run -t "<name pattern>"`。
- **断点调试**：开一个 JavaScript Debug Terminal，在里面跑上面的 vitest 命令，断点直接命中（对 agent-core-v2 这种无注释区包尤其好用——测试就是最好的文档）。
- 注意 `apps/kimi-code` 的 `test`/`e2e` 脚本自带 `pnpm -w run build:packages` 前置（依赖 packages 的 dist）；e2e 用 `pnpm e2e`（mock）与 `e2e:real`（真实 LLM，谨慎跑）。
- 例外：`packages/pi-tui` 用 **node:test**（`node --test test/*.test.ts`，CI 单独跑）；`apps/kimi-inspect` 的 vitest 不在根 projects 列表，要进它的目录跑。

## 6. 会话数据与回放：vis

```bash
pnpm vis
```

vis（`apps/vis`）可视化会话与回放：vis-server（API，默认 5174）+ vis web（默认 5173），由 `apps/vis/scripts/dev.mjs` 用 concurrently 同时拉起并协商空闲端口。学习 transcript / 事件流时，把一次真实对话放到 vis 里看事件时序，比读代码快。

## 7. 常用环境变量

| 变量 | 作用 |
|---|---|
| `KIMI_CODE_HOME` | 数据根（默认 `~/.kimi-code`）。调试时指向沙箱目录可完全隔离 |
| `KIMI_LOG_LEVEL` | 日志级别（`off`/`error`/`warn`/`info`/`debug`；测试里常见 `off`） |
| `KIMI_CODE_LEGACY_FLAG` | `=1` 强制 v1 引擎（CLI 的 `dev:cli:legacy`、插件引擎回退都会用到） |
| `KIMI_CODE_EXPERIMENTAL_FLAG` | 打开全部实验特性；单项用 `KIMI_CODE_EXPERIMENTAL_<NAME>`（清单见 `docs/en/configuration/env-vars.md` 与 `packages/agent-core-v2/docs/flag.md`） |
| `KIMI_CODE_DEV_SERVER` | dev 模式标记（容忍缺失 dist-web 等） |
| `KIMI_SERVER_URL` | kimi-inspect / code-app 的 web dev 指向哪个 server |

## 8. 已知坑

- `dev:server` / `dev:kap-server` / `dev:v2` 三个根脚本是**同一条命令**的历史别名，别纠结用哪个。
- `apps/kimi-inspect/README.md` 提到的 `dev:v1` 已不存在，等价物是 `dev:server`。
- 插件引擎切换（`kimi.useAgentCoreV1`）是启动时一次性解析的，改设置后必须 **Reload Window**。
- 插件 watch 不覆盖 `agent-core-v2`/`klient` 源码（见 §1），改引擎代码记得先 `pnpm build:packages`。
- 三个包（`agent-core-v2`、`kap-server`、`transcript`）禁止注释，别用"加注释辅助调试"的思路，临时标记用 `console`/断点。
