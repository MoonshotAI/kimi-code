# 00 · 项目全貌

> 时效基线：基于 commit `d4e0ad4b2`（2026-08）。行号会随代码演进漂移，以路径为准。

## 这是什么项目

Kimi Code 是 Moonshot 开源的 **AI 编程助手（coding agent）**，形态包括：

- **`kimi` CLI**（`apps/kimi-code`）：终端 TUI 交互式 agent，也即本仓发布到 npm 的 `@moonshot-ai/kimi-code`；
- **VS Code 插件**（`apps/vscode`）：侧边栏聊天式 agent，本学习路线的起点；
- **`kimi web`**（`apps/kimi-code` 的子命令 + `packages/kap-server`）：把同一引擎挂到本地 HTTP/WebSocket 服务上，供浏览器 UI 使用；
- **ACP 支持**（`packages/acp-adapter`、`packages/acp-server`）：把 agent 暴露成 [Agent Client Protocol](https://agentclientprotocol.com) 服务，供 Zed 等外部编辑器驱动。

所有形态共享同一套 **agent 引擎**。理解"一套引擎、多个宿主"是理解本仓的钥匙。

## 分层依赖图

箭头 = "依赖"。`apps/kimi-code` 和 `packages/node-sdk` 把引擎包声明为 devDependencies，因为构建时整体打进产物（tsdown 打包），代码层面是真实依赖。

```
┌─ L4 宿主 ────────────────────────────────────────────────┐
│  apps/vscode ──► node-sdk, migration-legacy              │
│  apps/kimi-code ──► agent-core-v2, kap-server, node-sdk, │
│                     acp-server, acp-adapter, pi-tui, …   │
│  apps/kimi-inspect ──► agent-core-v2, transcript         │
└──────────────────────────────────────────────────────────┘
┌─ L3 引擎的协议门面 ──────────────────────────────────────┐
│  node-sdk   （对外嵌入 SDK：vscode 插件、acp-adapter 用）│
│  kap-server （REST+WS 服务器：kimi web 用）              │
│  klient     （契约驱动的 facade，ipc/memory 两种传输）   │
│  acp-server / acp-adapter （ACP 协议适配）               │
└──────────────────────────────────────────────────────────┘
┌─ L2 引擎 ────────────────────────────────────────────────┐
│  agent-core-v2 （当前引擎：DI × Scope 架构）             │
│  agent-core    （v1 引擎：遗留回退用）                   │
└──────────────────────────────────────────────────────────┘
┌─ L1 叶子库 ──────────────────────────────────────────────┐
│ kosong（LLM 抽象，v1 用）· kaos（执行环境抽象，v1 用）   │
│ transcript · protocol · minidb · oauth · telemetry       │
│ pi-tui · tree-sitter-bash · migration-legacy             │
└──────────────────────────────────────────────────────────┘
```

注意：**agent-core-v2 不依赖 packages/kosong**，它在 `packages/agent-core-v2/src/kosong/` 内嵌了一份演化过的 LLM 抽象层。

## v1 / v2 双栈（重要）

仓库里并存两代引擎，学习主线**只走 v2**：

| | v1（遗留） | v2（主线） |
|---|---|---|
| 包 | `packages/agent-core` | `packages/agent-core-v2` |
| 架构 | `Agent` 类 + `KimiCore` 门面 | DI × Scope（依赖注入容器分层） |
| LLM 层 | `packages/kosong` | 内嵌 `src/kosong/` |
| 执行环境 | `packages/kaos` | 自带 `src/os/`、`src/runtime/` |
| 入口门面 | node-sdk `createKimiHarness` | node-sdk `createKimiHarnessV2`、klient、kap-server |
| 开关 | `KIMI_CODE_LEGACY_FLAG=1` 或插件设置 `kimi.useAgentCoreV1` | 默认 |

VS Code 插件 0.7.0 起默认跑 v2 引擎，保留一键回退 v1。v1 代码仍值得读（尤其 `packages/agent-core/src/loop/` 的状态机设计），放在学习后期速览（见 `06-支撑包速览.md`）。

## 一条消息的数据流（总览）

以 VS Code 插件发送一条聊天消息为例（详细版见 `02`，引擎内部见 `04`）：

```
webview（React UI）
   │ postMessage RPC（shared/bridge.ts 协议）
   ▼
extension host：BridgeHandler → KimiRuntime → SessionRuntime
   │ 进程内调用 @moonshot-ai/kimi-code-sdk
   ▼
node-sdk：SDKRpcClientV2（v2 默认）
   │ klient memory transport（JSON 往返 + zod 校验）
   ▼
agent-core-v2 引擎：agent loop（step/turn 循环）
   │ 组装上下文 → 选工具 → 调 LLM → 执行工具 → 循环
   ▼
内嵌 kosong 层 → Kimi/Anthropic/OpenAI 等 provider → LLM API
```

流式增量与工具事件沿同一条链路反向回到 webview 渲染。CLI 的 `kimi web` 路径则是把中间的"进程内调用"换成 kap-server 的 REST/WS，引擎侧完全一致。

## 核心包速查

| 包 | 一句话 |
|---|---|
| `packages/node-sdk`（`@moonshot-ai/kimi-code-sdk`） | 宿主嵌入 SDK：`createKimiHarness` / `createKimiHarnessV2`、`KimiHarness`、`Session`。VS Code 插件唯一依赖的引擎入口 |
| `packages/klient` | v2 引擎的契约驱动客户端 facade：`global.*` / `session(id).*` / `agent(id).*`，ipc / memory 两种传输 |

| `packages/kap-server` | Fastify REST+WS 服务器（`/api/v1`），把 v2 引擎暴露给浏览器/远程客户端 |
| `packages/agent-core` | v1 引擎（遗留） |
| `packages/kosong` | LLM/provider 抽象层（v1 栈使用） |
| `packages/kaos` | 进程/shell/文件系统执行环境抽象（v1 栈使用） |
| `packages/transcript` | 同构 transcript 渲染数据层（L1 存储→L4 视图注册），kap-server 与 kimi-inspect 使用 |
| `packages/minidb` | 嵌入式 JSON 文档库（快照+WAL+全文索引），kap-server 搜索的后端 |
| `packages/oauth` | Kimi OAuth 与托管鉴权工具 |
| `packages/protocol` | REST+WS 共享 schema（信封、错误码、分页） |
| `packages/pi-tui` | 内嵌的终端 UI 库（CLI 的 TUI 用） |
| `packages/tree-sitter-bash` | 纯 TS 的 bash 解析器（v2 引擎分析 shell 命令用） |

| `packages/acp-adapter` / `acp-server` | ACP 协议适配：v1（遗留 `kimi acp`）/ v2（`kimi acp --native`） |

## 新人最容易误解的几件事

1. **浏览器 Web UI 的源码不在本仓**。它在独立的 code-app 仓库开发，本仓只提交预构建产物 `apps/kimi-code/dist-web`。别去找前端源码。
2. **VS Code 插件不 spawn CLI、不连 kap-server、不用 ACP**——引擎直接跑在扩展宿主进程里，唯一的跨进程边界是 webview postMessage（详见 `02`）。
3. **`docs/` 是用户手册不是架构文档**；架构信息在各包 `AGENTS.md` 和 `packages/agent-core-v2/docs/`。
4. **三个包是"无注释区"**（`agent-core-v2`、`kap-server`、`transcript`）：除导出符号的 JSDoc 外不允许注释，`pnpm lint` 会检查。读代码时别指望注释，靠命名和 AGENTS.md。
5. **`KIMI_CODE_HOME`（默认 `~/.kimi-code`）是所有形态共享的数据根**：配置、会话、凭据都在里面，插件与 CLI 共用同一份。
