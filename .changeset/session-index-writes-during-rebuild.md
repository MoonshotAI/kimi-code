Keep the session summaries the read model mirror writes while a new session index generation is being built, and write them into that generation once it is published, so a session created or changed during the rebuild no longer goes missing or stale in session lists and counts until the next periodic reconciliation. Reconciliation and mirror flushes now take turns writing the published generation, so a session flushed while reconciliation runs is no longer counted twice; mirror flushes, `drain()` and session counts wait for a reconciliation in progress. Session counts also wait for an in-flight mirror flush, read the generation that is published at that point, and read again when a write lands mid-read. A project primary that changes during the rebuild now starts another rebuild right away, up to three rounds, instead of waiting for that reconciliation. The mirror now writes each session's working directory as derived from the project primaries of the generation it writes into, so a summary recorded under an earlier primary no longer overwrites the rebuilt one. Archiving or restoring a closed session now mirrors the working directory derived from the project's current primary instead of the directory stored in its metadata, and falls back to the stored one with a warning when the project cannot be read.
