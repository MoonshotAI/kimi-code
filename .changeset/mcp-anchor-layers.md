Split program MCP into a shared user layer (plugins and the user-level `mcp.json`) and reference-counted project layers keyed by anchor directory. An anchor is the nearest project root or checkout root above a session's working directory, falling back to the project root outside the project's registered directories, and pinned sessions re-evaluate it when those directories change. Sessions that follow the project root keep the previous servers, stdio directories and connection timing. Local sessions pinned to a working directory now load the project MCP files of their anchor instead of the project root's, so a session pinned inside a nested checkout no longer sees servers defined only in the project root's `.mcp.json` or `.kimi-code/mcp.json`; their session-provided stdio servers start in the pinned working directory, and trust disclosure lists the pinned anchor's servers. An invalid project MCP file now disables only that anchor's project servers instead of every MCP server. Checkout roots now come from the nearest `.git` entry, so an unparseable `.git` file stops the lookup instead of resolving to an enclosing repository. Pinned working directories, project roots and registered directories are compared by real path, so a symlinked spelling resolves to the same anchor. MCP servers no longer start after the session or layer that owns them has been released, including session-provided servers of a session closed before its first MCP load.
