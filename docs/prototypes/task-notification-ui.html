后台任务通知 · 状态通知卡（Notification card）

    
v2 —— v1 的「安静行」方案视觉权重过低（与 tool line 无法区分），改为参考 cron 通知与 toast/attention 卡的状态语义色。

    
针对 <notification>（origin kind = task_notification）目前被 messagesToTurns.ts 整条跳过、用户完全无感知的问题，把它渲染为聊天流中的一张状态通知卡。


    
视觉谱系：三种系统事件各就各位

    

      
事件形态语义

      
cron 触发右对齐来源标签 + accent 气泡「代替用户发言」，站在用户侧，权重 = 一条用户消息

      
后台任务通知（本方案）左对齐状态通知卡（soft 底 + bd 边 + 状态图标 chip）「agent 收到的系统事件」，站在助手侧，权重低于消息、高于工具行

      
compaction全宽 hairline 分隔条「上下文断裂」，是边界不是事件

    


    
卡片结构

    
    
      
  • 头行：28px 状态图标 chip（raised 底 + 状态色图标，沿用 sub-agent 卡的 pa-ic 语言）＋ 标题「后台任务完成 / 失败 / 超时 / 已终止」（text 色，medium）＋ 副标题（任务描述，mono 12px muted 截断）＋ 右侧状态词 · 时间 + chevron。整行可点，展开/收起。
    • 
      
  • 状态着色：completed → --color-success-soft/-bd；failed / timed_out / lost → danger 对；killed → warning 对；纯 info → 中性 --color-surface。全部取设计系统现成的状态 token 对（toast / qcard 同款），不新增色值。
    • 
      
  • 体部（默认收起）：字段区（type / source / severity，mono xs）、通知正文、输出文件行（raised 行 +「查看输出 → 右侧面板」「复制路径」）、「原始 payload」折叠块展示 <notification> XML 本体。
    • 
    


    
XML → UI 映射

    

      
notification 字段UI

      
type + severity卡片变体（ok / err / warn / info）+ 头行图标与标题动词

      
title头行副标题（mono 12px 截断）

      
category / source_kind标题主语：「后台任务」/「子代理」；体部字段

      
body / <output-file>体部正文 + 输出文件行

      
原始 XML体部「原始 payload」折叠块

      
id / source_id / agent_id仅体部字段区

    


    
行为规则

    
    
      
  • ① 到达即所见：turn 流式期间，通知卡 inline 插入真实到达位置（kimi-card-in 入场），不自动展开，不是 turn 边界——messagesToTurns.ts 的 continue 分支改为产出 TurnBlock{kind:'notification'}。
    • 
      
  • ② 连续并卡：相邻 ≥2 条通知（中间无 prose）并入一张中性组卡「N 条通知」，头行带每条的状态点串；展开后逐条紧凑行（22px 图标、0.5px subtle 分隔），每条可再展开自己的详情。
    • 
      
  • ③ 落定归档：turn settle 后，info/success 级卡随其他块折进「Worked Ns」；warning / error 级卡在 fold 外保持可见（需要人看的东西不进折叠），fold 行尾部追加一个 danger 点作线索。
    • 
      
  • ④ injection 仍隐藏：origin: injection（todo 提醒等 system-reminder）保持跳过，仅调试开关「显示注入的系统消息」下以 faint 行显示（演示里的「调试注入」按钮）。
    • 
      
  • ⑤ 联动：通知到达时 composer workbar 的后台任务 pill 计数 −1 并闪烁一次；「查看输出」打开右侧面板（复用 file-preview 轨道）。系统级 Web Notification 逻辑不变：通知卡管可追溯，系统通知管人不在时喊一声。
    • 
    


    
为什么不选这些

    

      
备选否决理由

      
安静行（v1，tool line 语言）权重过低：与工具行同节奏同色彩，事件被当成过程噪音一扫而过，失败通知尤其不该这么轻。

      
用户气泡 / 助手 prose机器生成的上下文，冒充任何一方发言都会污染对话语义，且会错误地成为 turn 边界。

      
compaction 式分隔条分隔条表达「上下文断裂」，语义过重；通知是事件不是边界，多条通知会把流切碎。

      
仅 toast短暂、不可回溯，解决不了历史断裂；失败通知也不该自动消失。

      
通知中心（铃铛面板）与托盘 attention + workbar pill 职责重叠；把事件抽离时间线，追溯时要在两处对照。可作为后续增强，不替代流内卡。

    


    
边界情况

    
    
      
  • coalesced 通知（coalescedCount > 1）：单卡展示，状态词改「完成（合并 N 次）」，体部说明。
    • 
      
  • 无输出文件：隐藏输出行，只留字段与正文。
    • 
      
  • 子代理通知（带 agent_id）：图标换 sub-agent 语义，标题主语「子代理」，详情可跳 sub-agent 面板。
    • 
      
  • a11y / 动效：头行是 bare <button aria-expanded>；prefers-reduced-motion 关闭入场动画；亮暗双主题全部走 token。
