设计思路：Agent 时代的多 Workspace / 多 Session 任务管理

1 · 要解决的问题

  • Session 没有生命周期状态——进行中和已完成无法区分。现状只有瞬时状态（spinner / 待批准 / 未读点）和一个终态「归档」，中间是断的：agent 跑完、你看完，会话就悬在那里，和正在跑的看起来没区别。
  • 工作空间入口承载两个意图——「在这个目录建任务」和「切到这个目录看代码 / 切分支」，今天它们被混在同一个分组列表里。
  • 旧会话无脑堆积——做完的、放弃的、跑完没人看的，全堆在一个按时间排序的列表里，没有出清机制。

2 · 核心判断：稀缺的是注意力，不是 session

Agent 任务和人的任务（Linear/Jira）有本质区别：创建成本极低（一句话）、状态机器可观测（系统知道在跑 / 在等你 / 跑完了）、并行度高（同时挂五个不稀奇）、产出是工件（diff / PR）。因此瓶颈是用户的注意力，整个架构围绕「注意力分配」组织，而不是围绕「列表组织」。多任务场景下唯一重要的头部指标是：等你的有几个。

3 · Session 生命周期：机器能判的，不让用户判

草稿→ 运行中⇄ 待处理等你批准/回答→ 待验收跑完还没看→ 进行中·挂起→ 已完成 已放弃
  • 运行中 / 待处理 / 待验收系统全部知道（spinner、Approve 徽章、未读点就是它们的外显），用户一个都不用标；用户只声明终态。
  • 终态双轨：「做完了」和「不做了」是两个语义，合并会让已完成列表失去成绩册的价值。
  • PR 有客观终态事件（merge），session 没有——所以 Done 靠手动零摩擦 + 系统建议两条腿。

4 · 信息架构：三个 tab 各管一件事

Tab职责回答的问题
进行中注意力队列（默认视图）：排序 = 待处理 > 待验收 > 运行中 > 挂起；tab 上的圆点按最高优先级状态变色「现在需要我干什么？」
已完成出清后的档案：时间倒序，不分组不清理，回收靠 ⌘K 搜索「那个任务最后怎么收的？」
工作空间环境入口：只列目录，点击 = 进入该环境（草稿态，不占列表）「我要在哪个目录干活 / 看代码？」

关键取舍：workspace 是资源上下文（分支、文件、终端、编辑器），session 是跑在其上的任务。队列里 workspace 降为行内元数据（cwd 小字），不再作为分组维度——把项目维度塞进注意力队列，队列就碎了。层级关系：状态 tab 是上层（回答「要不要我看」），平铺/分组是 tab 内的展示层（回答「怎么摆」），两者不再并列。

5 · 三个关键机制

  • 完成零摩擦：行 hover、正文 header、右键菜单三处入口；免确认，撤销 toast 是全部仪式。功能价值完全取决于完成率，入口密度比标签本身重要。
  • 系统建议完成：PR merged → toast 建议标完成。v2 git domain 已经把 PR 状态喂到行上，这是精确且几乎免费的信号；后续可加「N 天未动 → 建议完成」。只建议，不自动。
  • 目录主页（落地态）：点击目录不跳 tab，正文落在该工作空间的主页——composer + 分支 + 在编辑器打开 / 终端 + 该目录近期会话。「建任务」与「看环境」在此统一：发消息才创建 session，不发消息什么都不会产生。

6 · 明确不做

  • 不做看板拖拽——agent 任务生命周期以分钟计，手动挪状态是家务活；
  • 不再加层级——workspace > session 两级封顶，subagent / todo 收在 session 内部；
  • 完成不加确认弹窗、已完成不做分组 / 清理策略——没人浏览两百条的已完成列表。

7 · 与现状的差量

八成已存在：瞬时状态（徽章 / spinner / 蓝点）、注意力计数（pendingBySession）、PR 状态信号（git domain）、草稿语义（首条消息才建 session）。增量只有三个：

  1. 用户可声明的终态（Done / 放弃双轨；若复用 archived 换皮则不动 server）；
  2. 进行中 tab 从时间序改为注意力序；
  3. 工作空间目录 tab + 落地主页。

上方 demo 已覆盖 ① 的骨架与 ③（目录 tab + 工作空间主页）；注意力排序是下一步。

Demo 交互映射与待定问题

交互映射（对现状的改动点）

  • 标签页 = 设计系统 SegmentedControl（sm 全宽变体），是状态维度的上层结构；「平铺 / 按工作空间」不再是并列视图，降为进行中 / 已完成 tab 内的展示切换（列表头右侧的 list/tree 开关）。
  • Session 行 hover 的 归档 按钮 → 完成（✓ 图标，hover 呈 success 色）；右键菜单里的「归档」 → 「标记为完成」。
  • Open / Done 用彩色状态图标（圈点 / 圈勾，GitHub issue 列表语言），色值：--color-success / --color-done。
  • 正文 header 右侧新增主行动按钮「完成」（Button sm / primary），完成后变为紫色 Done pill + 「重新打开」，对齐 PR Merge → Merged 的位置与语义。
  • 完成的确认/撤销复用归档的 undo toast，不引入新的打断式弹窗。

待定问题（本 demo 先按加粗项演示）

  • 完成时是否自动取消置顶：是（置顶区只放进行中的会话）。
  • 「工作空间」tab 不再罗列 session：只显示目录；点击目录 = 在该工作空间起草稿——不跳转 tab，正文变为新会话空状态，发送首条消息后才计入「进行中」；⋯ / 右键菜单保留复制路径、重命名、移除。
  • 「平铺 / 分组」视图切换：降为 tab 内的展示开关，进行中与已完成各自可切；工作空间 tab 只列目录，不涉及。
  • 已完成 tab 的行 hover 只留「重新打开」，不再给置顶。
  • 「完成」是否要求二次确认：否，toast 撤销即可（与归档一致）。
