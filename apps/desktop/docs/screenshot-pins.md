# 贴图窗口

贴图只作为桌面参考图片。显示、点击、拖动、缩放或关闭贴图不能激活主应用，也不能主动恢复主窗口。关闭按钮、双击图片与右键菜单都销毁同一个贴图窗口并释放图片。

## 窗口与缩放

- `screenshot-output.ts` 创建无框、直角、不透明、不可聚焦的窗口，等待图片加载与实际绘制完成后用 `showInactive()` 显示，并将新贴图移到置顶窗口最前方。加载失败、超时或截图取消会销毁待显示窗口，失败时保留截图编辑器。macOS 使用 `panel` 类型；跨桌面显示不切换应用的进程类型。
- 图片等比放入窗口，极细长图片与最小窗口尺寸冲突时保留白色边距，不拉伸图片。原生窗口保持不透明以支持系统缩放。
- macOS 和 Linux 边缘与角点使用系统缩放，`setAspectRatio()` 保持原图比例。Windows 图片边缘与角点提供 6 DIP 命中区域，经专用 IPC 等比缩放，固定相对角点并限制在当前屏幕工作区内。滚轮仍由贴图页面经专用 IPC 调整尺寸，主进程按原图比例计算高度并限制屏幕内的最大大小。

贴图的移动、滚轮缩放和边缘缩放共用主进程保存的目标矩形，通过 `setBounds()` 一次提交位置与尺寸，避免 Windows 无框窗口的原生边框与 DPI 取整误差在逐帧读写中累积。每次操作通过 `getPosition()` 读取系统实际位置，以跟随显示器或工作区变化造成的自动重定位，尺寸仍使用缓存值。Windows 和 macOS 只有用户完成系统缩放时通过 `resized` 读取实际矩形，普通 `resize` / `move` 通知不回写目标矩形；Linux 不支持上述缩放完成事件，改由 `resize` 同步系统窗口尺寸。所有提交的坐标归一化为有符号 32 位整数并消除负零；负屏幕坐标保持有效。系统宽高比约束只在 Windows 禁用。

## macOS 非激活补丁

Electron 43.1.1 的 `ElectronNSPanel` 继承自 `NSWindow`，通过覆盖 `styleMask` 报告非激活标记，并非真正的 `NSPanel`。本机真实鼠标测试确认：仅设置 `type: 'panel'`、`focusable: false` 和 `showInactive()`，点击仍会激活应用。

现有 `screenshot-overlay.node` 新增 `configurePin()`，仅对贴图调用 `_setPreventsActivation:YES`，并禁用窗口动画。不修改应用全局激活策略，不在关闭后强行切回其他应用，也不改截图编辑窗口的键盘焦点。

这是 macOS **非公开接口**，存在系统升级风险。调用前检查 `respondsToSelector`；若不可用，销毁尚未显示的贴图并返回 `nonactivating-pin-unsupported`，不留下抢焦点或无法操作的窗口。升级 macOS 或 Electron 时必须重新执行下列实机检查；若 Electron 原生修复此问题，应移除该补丁。

## 验收

2026-09-21：Windows 单屏 200% 与通过 Electron `--force-device-scale-factor` 强制的 125% / 150% 均通过真实窗口自动检查。每档创建 10 张贴图，每张经 preload IPC 连续移动 1,000 次（含小数位移），前后矩形一致，移到原点附近无异常；像素、置顶、非聚焦、独立关闭和坏图清理检查也通过。运行 `pnpm --filter kimi-code-app exec node scripts/check-screenshot-pin.mjs --force-device-scale-factor=1.25` 可复验指定缩放。此检查使用程序发送移动指令，尚未覆盖真实鼠标和跨不同 DPI 显示器拖动。

先将其他应用置于前台，再通过真实鼠标事件操作贴图，不能仅用 DOM `click()` 或模拟窗口代替。

- 显示贴图、普通点击、拖动图片不改变前台应用
- 点击右上角关闭按钮、双击图片、右键关闭后，前台应用与主窗口显示状态不变
- 拖动边缘或角点可以放大和缩小，宽高比不变
- 滚轮仍可缩放，后续关闭不会跳到主应用
- 多张贴图各自独立，关闭一张不关闭其他图片
- 主应用自身处于前台时也能关闭贴图，不隐藏或最小化主窗口

Windows 使用相同的不透明窗口与非聚焦显示，不加载 macOS 模块。隐藏窗口不能依赖 `ready-to-show` 才请求显示；图片就绪后先完成页面加载，再通过 `capturePage` 请求实际绘制，成功后显示。Windows 实机结果单独记录，不能以 macOS 测试通过替代。

Windows 使用 `screen-saver` 置顶层级；当前 Electron 的 `floating` 层级会进入任务栏后方放置逻辑，实机上丢失置顶状态。绘制服务首次尚未就绪时，仅对 `UnknownVizError` 做最多 10 次、间隔 25 毫秒的短暂重试，整个贴图加载限时 10 秒。

2026-09-15：Windows 11 双屏（200% / 150%）连续 10 次创建、置顶、非聚焦、像素、独立关闭及坏图清理检查通过；首次 721 毫秒，后续 240–364 毫秒。真实鼠标验证拖动、滚轮缩放、角点从 720 × 360 缩小至 560 × 280、右键关闭及 X 关闭。构建 renderer 后运行 `pnpm --filter kimi-code-app exec node scripts/check-screenshot-pin.mjs` 可复验窗口与图片检查；此脚本不替代真实鼠标验证。

2026-09-10 本机验证：使用实际主进程代码、原生模块、贴图页面及预加载桥接，以真实鼠标点击和角点拖动测试。主窗口可见但其他应用在前台时，普通点击、X 关闭、双击关闭及多贴图独立关闭均保持原应用在前台；角点从 400 × 200 调至 500 × 250，滚轮随后调至 550 × 275，均保持 2:1。右键菜单、主应用在前台及 Windows 实机仍需人工复验。
