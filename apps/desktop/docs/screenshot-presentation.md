# macOS 截图空白帧排查

## 问题与修复

截图窗口原来是不透明黑底，页面预热及退出清空 `img.src` 后会产生黑色页面帧。真实 Electron 43.1.1 的 640 × 400 pt 隐藏窗口测试中，这两个阶段的像素全部不透明，其中约 99% 为纯黑。图片本身没有缩放或淡入淡出动画，原生窗口也已禁用动画。

macOS 原先只等图片解码、Vue 更新及两次动画帧回调，而窗口 `ready-to-show` 只报告首次预热画面；这些条件没有验证每次截图最后生成的页面画面。退出的 `hide()` 和页面清空也没有跨进程、窗口系统的逐帧交接保证。

修复调整 macOS 窗口背景为透明，空页面透明，隐藏未就绪的图片占位，并把已有的页面绘制检查扩展到 macOS。保留 macOS 的动画帧等待：真实重复截图测试发现，图片解码及 Vue 更新后，甚至经过动画帧回调，仍可能读取到上一次清空的画面。

macOS 还会把读回图像缩小到一个像素，检查其透明度是否完全不透明；透明旧帧不算就绪，间隔 16 ms 再次读取。正常完整画面不增加等待，重试受原有就绪超时和取消状态约束。Windows 保留已有检查与窗口透明性设置。

## 验证

```sh
pnpm --filter kimi-code-app run build
pnpm --filter kimi-code-app exec electron tests/smoke/screenshot-presentation.cjs
```

该测试使用真实构建的截图页、独立数据目录和隐藏窗口，不读取用户桌面、不改变安装应用。连续三轮验证：

- 预热及退出清空后，所有像素透明，没有不透明黑白底。
- 图片就绪并读取页面后，所有像素不透明，截图完整覆盖页面。
- 页面读取不会提前显示原生窗口。
- 进入编辑后默认显示单行评论框，不抢焦点，添加按钮显示 Enter 提示。

主进程测试另行覆盖多屏等待、重复使用窗口、透明旧帧重试、重试取消和超时、绘制失败，以及取消后迟到的绘制结果不得重新显示窗口。渲染测试覆盖图片解码期间和退出后的占位隐藏。

这些测试确认了空白帧来源和修复后的页面帧，不等同于屏幕录像逐帧验收。系统合成、外接屏和 HDR 的最终显示仍须用实际安装包走查。

相关接口：[Electron capturePage](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts)。
